# bindi — the bar

What a green means in **bindi 🐨**, and what it does not. A green here is not the same assurance as a green in a sibling repo; read this before quoting one.

**For testing only, not for use with real patients.** A gallery is an in-silico hypothesis, not a validated result.

## The bar

```bash
pip install -e .     # or: uv pip install -e .
pytest               # 101 passed (11 skipped without mmseqs2 on PATH)
bindi run campaigns/pdl1.json --dry-run   # curation smoke-test on fixtures, no GPU
```

`pytest` green is bindi's bar. The dry-run exercises the curation path and gallery layout without a GPU; it does not replace binding or structural validation.

## What a green covers

- **Manifest disclosures** (`test_five_disclosures_release_and_claim`) — the five fixed disclosure lines, `release: false`, and the `not_a_release` reason are present; a test fails if any of the five is missing.
- **Relative-only claim** (`test_claim_field_present_and_relative`, `test_no_key_looks_like_absolute_affinity`, `test_absolute_affinity_detector_*`) — the `claim` field is present and relative, and no manifest or score key reads like an absolute affinity or kcal/mol value.
- **Rank is a pass signal** (`test_rank_labelled_as_pass_signal_not_potency`) — `rank_meaning` records `rank` as a pass-signal ordering, never potency or affinity.
- **Reproducible given a seed, not "deterministic"** (`test_reproducibility_not_deterministic`) — `reproducibility.model` is `reproducible-given-seed`, with `seed` and `trajectories` where the campaign provides them; the word "deterministic" is never used for the design step.
- **Benchmark honesty** (`test_benchmark_record_present_and_unchecked`) — the `benchmark` record is present and cited, and its status is `unchecked`; no correlation number is fabricated.
- **Licence tiers** (`test_deployable_path_rejects_evaluation_only_tools`, `test_deployable_path_accepts_deployable_tools`, `test_tool_tiers_are_cited`, `test_curate_manifest_tooling_is_deployable`) — `evaluation_only` tools (FEP+, PyRosetta, PBEE) are rejected from any lab-facing path; deployable tools pass; every tier is cited.
- **Provenance** (`test_provenance_present`) — every design is marked an in-silico hypothesis until confirmed experimentally.
- **Fixture-path disclosure** (`test_dry_run_pipeline_builds_gallery`, `test_fixture_path_statement_required_when_fixture_path_used`) — dry-run / fixture-path galleries carry a non-empty `fixture_path_statement` in plain language; a test fails if it is missing or empty when the fixture path was used.
- **Structures recorded** (`test_structures_not_run_recorded_when_none_copied`, `test_structures_copied_status_when_mm_cif_present`) — `structures.copied` is explicit; when zero, `status` is `not_run` with a `reason`, not silence.
- **Ensemble off by default** (`test_default_run_emits_no_ensemble_field_anywhere`, `test_default_run_does_not_reorder_by_ensemble`, `test_enabled_path_emits_full_ensemble`, `test_enabled_via_policy_flag`, `test_enabled_path_reorders_by_consensus`) — by default no `ensemble` field is written and no reorder happens; enabling it explicitly restores the full block, and both paths are tested.
- **Ensemble internals** (`tests/test_ensemble.py`) — ranking, disagreement summary, triage, and not-comparable handling (fewer than two universes, missing/blank/non-numeric metric).
- **Clinical case seam** (`tests/test_case_seam.py`) — a case record validates against the documented fields (required fields, enums, `SYNTH-` ids, peptide and HLA patterns, mutant ≠ wild-type, same length, restriction allele present in `class_i`); the target is extracted from the record; the fixture fallback is intact; the hold conditions (signed record, human-reference `pass`, stated margin, **established structural margin threshold**) are enforced in code, including a `DesignHold` from `generate(dry_run=False)` before BoltzGen is called; and one `case-run` writes one JSONL trace whose ten stages carry their honest statuses.
- **Margin stage refuses, and says what is missing** (`tests/test_margin_refusal.py`) — `margin.SIGNED_STRUCTURAL_SCORER_IDS` is empty, no combination of scorer id and evidence level can return `threshold_status: established`, the `not_computed` refusal names the missing requirement (a structural scorer whose margin threshold has been signed off for the Boltz-based pipeline), sequence-level scorers never clear the stage, and no margin number is written. Replaces the deleted BindCraft-on-Modal tests; BindCraft is no longer in the design path.
- **ipSAE vetoes, and can never bless** (`tests/test_ipsae_veto_only.py`) — the veto-only filter (`src/bindi/ipsae_veto.py`) may refuse a design and may never pass, rank-promote or certify one, and the asymmetry is structural: a decision has no truth value to mistake for a pass, a decision may carry an ipSAE number only when it is a veto (so no survivor has a score anywhere to rank on), `apply_veto` returns the surviving design objects unmodified and in order, an unset veto floor is inert rather than permissive, and no default floor exists in code. Acting only on the negative result needs no signed threshold, because a poor score vetoes while a good score asserts nothing. Vetoing changes nothing about the margin stage, which still refuses.
- **The ipSAE caveat travels in the output** (`tests/test_ipsae_veto_only.py`) — every record carrying an ipSAE-derived number carries `ipsae_margin.CAVEAT` verbatim: no orthogonal re-predictor and no experimental anchor in this repository, error peptide-dependent and not cancelling under subtraction, any threshold signed off it provisional until wet-lab confirmation.
- **The case record and the campaign are about the same peptide** (`tests/test_nyeso1_case_record.py`) — `fixtures/immunology_case_NYESO1_A0201.json` carries `SLLMWITQC`, derived from `wetware-hq/wing` `fleets/NYESO1-A0201/CASE.md`, and is UNSIGNED: a clinical signature cannot come from an agent. It declares `antigen_class: shared_cancer_testis`, which forbids a wild-type peptide SEQUENCE (there is no variant, so inventing one would fabricate clinical content) and in exchange requires the specificity panel and the `on_target_minus_best_decoy` endpoint — a tightening, not a relaxation, and the design hold stays fully in force either way. The retired placeholder (`YLDPETGDW`) is no longer any campaign's case record.
- **Candidate structural scorer does not clear the margin** (`tests/test_ipsae_margin_candidate.py`) — ipSAE is registered as a candidate (`ipsae_boltz_cpu_v1`, evidence level `interface_pae_from_boltz_prediction_not_a_binding_measurement`) with working plumbing, and the margin stage still refuses: `SIGNED_STRUCTURAL_SCORER_IDS` is still an empty frozenset, no combination of scorer id and evidence level returns `established`, the refusal wording is pinned byte-for-byte, no threshold number exists in `margin.py` or `ipsae_margin.py`, a margin computed from the candidate is `stated` but does not clear the stage, and the scorer refuses rather than inventing a number when a prediction is missing or an interface is ambiguous. What would be needed to sign a threshold is `docs/PROPOSAL-ipsae-structural-margin.md`, a proposal, not code.
- **Hosted Boltz API is the only generator path** (`tests/test_boltz_hosted.py`) — no local-binary entry point survives (`boltzgen_executable`, `build_boltzgen_command`, `maybe_rerank_with_boltzgen`, `BOLTZGEN_CMD` all gone; neither `boltz.py` nor `generate.py` imports `subprocess`); the client authenticates with `BOLTZ_API_KEY` in an `x-api-key` header and fails closed without one, before any network call; the credential never appears in a request body or provenance record; the request body matches the documented design shape with 0-based per-chain epitope indices; and every test uses an injected transport, so none touches the API.
- **APPR spend gate blocks submission** (`tests/test_boltz_hosted.py`) — submission is refused with no approval, and with an approval that is unapproved, unsigned, uncapped, over-cap, unpriced, expired, wrongly-schema'd, `on_deny`-weakened, or pinned to a different `request_sha256`; a closed gate never reaches the transport; `bindi generate` on a real run returns `status: "refused"` and writes no `run.json`; and nothing inside bindi can open the gate. A green says a submission is correctly refused, not that one has ever succeeded.
- **Immunology design spec** (`tests/test_design_spec.py`) — `campaigns/nyeso1_a0201_pmhc.yaml` parses, matches the three-chain NY-ESO-1 157-165 / HLA-A*02:01 complex in `CASE.md` (275/99/9 residues, peptide `SLLMWITQC`, epitope 0-8), invents no `non_binding_residues` panel and no campaign size, and records in the file what still needs Mathew's judgement; the immunology campaign policy resolves it. A green says the spec is well-formed and honestly annotated, nothing about whether it should be submitted.
- **Compute configuration as code** (`tests/test_infra_config.py`) — `modal_infra.json` parses, every declared function carries a positive `cpu`/`memory`/`timeout` and a stated purpose, no function declares a GPU (with the reason stated in the file), `modal_infra.json` is added into the image, and `modal_app.py` reads it at import time, pins its sha256 and parameterises every declared function from it. A green says nothing was deployed.
- **Policy & pipeline** (`test_bare_bindcraft_json_normalizes`, `test_legacy_bindcraft_key_migrates_to_boltz`, `test_legacy_design_block_still_resolves_a_target`, `test_resolve_paths`, `test_dry_run_pipeline_builds_gallery`, `test_curate_existing_campaign`) — legacy campaign JSON normalizes to `boltz`, paths resolve, and the dry-run and re-curate paths build a `bindi.gallery.v1` gallery.

## What a green does NOT cover

- **The ensemble heuristic is unvalidated.** It ships **off by default** and is a ranking heuristic, never a safety claim; its benchmark status is `unchecked`. A green does not say it ranks correctly.
- **Binding, structural, or experimental validity.** `rank` is a pass signal from Boltz-2 confidence metrics, not measured affinity or potency. A gallery is a hypothesis until confirmed in the lab.
- **No hazard screen** has been applied to any gallery; `release` is always `false` and `not_a_release` names the unmet condition.
- **Identity and sign-off gates are specified but unbuilt.** The disclosure lines say so; a green does not mean they exist.
- **The end-to-end immunology case.** `case-run` is fixture-backed: `design` is `fixture_backed`, `margin_wild_type` is `not_computed`, `human_reference_gate` is `unbuilt`, and `ward_handoff`/`letter` are `not_invoked`/`not_produced`. A green says those statuses were reported honestly, not that any of those steps happened.
- **A cleared margin stage.** `margin_wild_type` cannot reach `established`: there is no structural scorer whose threshold has been signed off for the Boltz-based pipeline, and the code has no branch that would return one. A green means the refusal is well-formed and names what is missing — nothing about binding.
- **A submitted design run.** Nothing in this repository has been submitted to the hosted Boltz API and nothing has been spent. The submission path is exercised only against an injected transport.
- **The human-reference gate.** When a reference FASTA is supplied the gate is exact k-mer containment only: no alignment, no substitution matrix, no E-value, no immunogenicity assessment. A `pass` does not mean a design is not cross-reactive.
- **Not a release.** The gallery manifest is marked `not_a_release`; a green is a code check on invented fixtures, not evidence of clinical safety.

## Name guard

Not feasible as a hard test here, and not faked. Unlike the sibling harness repos, bindi has no registry of named check ids (no `WG-`/`PM-` scheme); its checks are the pytest functions listed above, named by the test runner itself. There is no separate "check name" a run could use that this file could diverge from, so a name-guard test would assert nothing. Keep this list in step with `tests/` by review instead.
